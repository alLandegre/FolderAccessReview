# Folder Access Review

**Folder Access Review** — локальное Windows-приложение для **аудита NTFS-прав** на папках файлового сервера (и локальных дисках).  
Программа **только читает и показывает** ACL: не назначает и не снимает права.

---

## Кому полезна

| Кому | Зачем |
|------|--------|
| **Администраторы файловых серверов / AD** | Быстро увидеть, кто имеет доступ к каталогам проектов и вложенным папкам |
| **Служба ИБ / аудит** | Найти «забытые» временные прямые назначения пользователям |
| **Владельцы данных / бизнес-админы** | Понять, какие группы и пользователи висят на шаре без ручного обхода в проводнике |
| **Поддержка** | Ответить на вопрос «почему у сотрудника есть доступ к этой папке?» по дереву и по базе пользователей |

Типичный сценарий: шара вроде `\\fileserver\Share\Projects\` с десятками/сотнями проектов и вложенными каталогами. Права шаблонные, но иногда вручную выдают временному сотруднику **чтение**, а потом забывают снять.

---

## Что умеет сейчас (v1.5)

- Выбор корневой папки (UNC или локальный путь) и **глубины** обхода (без спуска до каждого файла)
- Дерево папок + таблица ACL выбранного каталога
- **Явные** и **унаследованные** ACE с фильтром
- Имена субъектов: `DOMAIN\user` / группа
- Уровни в стиле проводника: Полный доступ, Изменение, Чтение и выполнение, Чтение, …
- Участники **групп безопасности** (раскрытие из AD)
- По клику на субъект — **все каталоги текущего скана**, где он встречается (◆ в дереве)
- Вкладка **«Пользователи»**: локальная SQLite-база **только прямых ACE пользователей** (для поиска забытых персональных прав)
- Выбор **папки базы** (в т.ч. общая `ProgramData` для работы под доменным админом и рабочей УЗ)
- Экспорт в **CSV / XLSX**
- Установщик Inno Setup (per-user) и портативные сборки по версиям

**Жёсткое ограничение:** приложение **read-only** по ACL — нет изменения прав.

## Стек

- .NET 8, WPF
- NTFS ACL: `System.IO.FileSystem.AccessControl`
- AD: `System.DirectoryServices.AccountManagement`
- БД: SQLite (`Microsoft.Data.Sqlite`)
- Экспорт: ClosedXML
- Установщик: Inno Setup 6

## История версий и функционал

### 1.0 — MVP
- Сканирование с ограничением глубины
- Только **явные** ACE
- Дерево папок, фильтры (пользователи/группы, Allow/Deny, поиск)
- Экспорт CSV/XLSX
- Self-contained publish

### 1.1 — Наследование
- Показ **унаследованных** ACE наряду с явными
- Колонка «Наследование»
- Фильтр: Все / Только явные / Только унаследованные
- Сводка «Явных: N, унаследованных: M»
- Исправление сценария, когда на вложенной папке права только унаследованы (в 1.0 таблица казалась пустой)

### 1.2 — Участники групп
- Клик по **группе** в таблице ACL → список прямых участников из AD
- Вложенные группы раскрываются стрелкой (ленивая подгрузка)

### 1.3 — Каталоги субъекта по скану
- Клик по пользователю/группе → список **всех папок текущего скана**, где есть этот ACE
- Переход к папке из списка, метка **◆** в дереве
- Кнопка «Сбросить» фокус субъекта

### 1.4 — База пользователей (забытые прямые права)
- После скана в SQLite пишутся только **явные ACE пользователей** (не группы, не унаследованные)
- Вкладка **«Пользователи»**: поиск → выбор УЗ → список папок, уровень, даты
- При повторном скане пропавшие назначения помечаются «Не найдено в последнем скане»
- Файл БД по умолчанию: `%LocalAppData%\Folder Access Review\user-access.db`

### 1.5 — Выбор папки базы
- На вкладке «Пользователи»: **Обзор…**, **ProgramData (общая)**, **По умолчанию**
- Настройка пути сохраняется в `%LocalAppData%\Folder Access Review\settings.json` (для каждой Windows-УЗ отдельно)
- Сценарий: сканируешь под доменным админом в общую папку (`C:\ProgramData\Folder Access Review`), под рабочей УЗ указываешь тот же путь — одна база

## Установка и запуск

### Установщик (рекомендуется)

Собранный Setup (если есть локально после сборки):

`installer\FolderAccessReview-Setup-1.5.0.exe`

- Установка **только для текущего пользователя**
- Ярлык и запись в «Установка и удаление программ»: **Folder Access Review**
- Каталог: `%LocalAppData%\Programs\Folder Access Review`

Сборка установщика из исходников:

```powershell
.\setup\build-installer.ps1
```

Нужны: .NET 8 SDK, Inno Setup 6.

### Портативный запуск

Локальные self-contained сборки (обычно не в git из‑за размера ~170 MB):

```
Приложение\
  1.0\
  1.1\
  …
  1.5\FolderAccessReview.exe
```

Сборка портативной версии:

```powershell
dotnet publish src\NeFs.AclAuditor\NeFs.AclAuditor.csproj -c Release -r win-x64 --self-contained true -o "Приложение\1.5"
```

### Из исходников

```powershell
dotnet restore
dotnet build NeFs.AclAuditor.sln -c Release
dotnet run --project src\NeFs.AclAuditor\NeFs.AclAuditor.csproj -c Release
```

## Как пользоваться

### Сканирование ACL

1. Запусти программу под учёткой с правом **читать ACL** (часто — доменный администратор).
2. Укажи путь (`\\fileserver\Share\Projects\2024` или локальный) и **глубину** (часто 2–3).
3. **Сканировать** → слева дерево, справа ACL выбранной папки.
4. Фильтры: субъект / Allow-Deny / наследование / поиск.
5. Клик по субъекту → каталоги по всему скану; клик по группе → ещё и участники.
6. При необходимости — **Экспорт…**.

### База «забытых» прямых прав

1. После скана данные пользователей автоматически попадают во вкладку **Пользователи**.
2. Выбери `CORP\j.smith` → список папок с прямыми ACE.
3. Если работаешь под разными УЗ Windows — на обеих выставь **одну** папку базы (кнопка **ProgramData (общая)**).

## Требования к среде

- Windows 10/11 (или сервер с GUI)
- Доступ к целевой шаре по SMB/UNC
- Права на чтение NTFS ACL
- Для участников групп — доступ к домену (LDAP/AD)

Нагрузка на файловый сервер при глубине 2–3 и сотнях/тысячах папок — обычно небольшая: читаются метаданные каталогов и ACL, **не** содержимое файлов и не объём шары в терабайтах.
